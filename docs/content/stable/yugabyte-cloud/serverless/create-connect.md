## Create a serverless cluster

If you have previously created a serverless cluster, do the following:

1. Switch to your Serverless account.
1. On the **Clusters** page, click **Add Serverless Cluster** to open the **Create Cluster** wizard.

The **Create Cluster** wizard has the following pages:

1. [General](#general)
1. [Cluster Settings](#cluster-settings)
1. [Network Access](#network-access)
1. [DB Credentials](#db-credentials)

### General

Set the following options:

- **Cluster Name**: Enter a name for the cluster.

### Cluster Settings

#### Engine

**PostgreSQL** is the default. **AI Database**, **Oracle**, **SQL Server**, and **DocumentDB** are the other engines.

The engine determines which [extensions](#extensions) can be included.

#### Read-write compute

Choose a size:

- **Small/Free**: 2 vCPU and 16 GB.
- **Medium**: 4 vCPU and 32 GB.
- **Large**: 8 vCPU and 64 GB.
- **Custom**: Select **vCPU** and **Memory**. vCPU can be from 0.5 to 64; add `m` to enter values in millicores (for example, `1500m`). Memory can be from 1 to 512 GB; you can also enter values in MiB. You must have at least 8 GB per vCPU.

    Your organization is allowed one Free cluster. If you choose an option other than Free and you have not added a [billing profile](../../cloud-admin/cloud-billing-profile/) to the account, you will be prompted to create a billing profile before the cluster is created.

#### Extensions

Select PostgreSQL extensions that you want to use with your cluster.


Extensions that the engine includes are marked **Included with engine**.

The cluster starts with a `main` branch, and you can [fork other branches](../manage/#add-a-branch) from it. The extensions you select are seeded on `main`, and every branch forked from it inherits these extensions. You can add extensions to a branch later. You cannot remove them.

For information on extensions supported in YugabyteDB, see [PostgreSQL extensions](../../../additional-features/pg-extensions/).

### Network Access

Select a **Connectivity Method**. This determines how clients connect to the cluster.

**Public Endpoint** is the default. Enter **Trusted IP Addresses**. Each entry is one address or a CIDR range. Separate several entries using commas.

{{< warning title="Important" >}}

A public endpoint with no trusted IP addresses accepts connections from anywhere on the internet. The database password is the only protection. Do not use `0.0.0.0/0` for production data.

{{< /warning >}}

### DB Credentials

The database admin credentials are required to connect to the YugabyteDB database that is installed on the cluster.

The database user is `cloud_admin`. You can use the default password generated by YugabyteDB Aeon, or add your own.

{{< warning title="Important" >}}

Save the credentials file. You need it to connect, and the console does not show the password again.

{{< /warning >}}

Download the credentials, and click **Create Cluster**.

YugabyteDB Aeon adds the cluster to the **Clusters** page. A new cluster has one read-write endpoint, on the main branch. An endpoint consists of the connection URL, compute size, and network access settings.

## Connect

Connect to your serverless cluster using [psql](https://www.postgresql.org/docs/15/app-psql.html).

The connection string is as follows:

```sh
psql "host=<HOST_ADDRESS> port=55433 user=<DB USER> dbname=postgres sslmode=verify-full sslrootcert=<ROOT_CERT_PATH>"
```

To obtain the connection string for your cluster endpoint, do the following:

1. On the **Clusters** page, open the serverless cluster.

1. Select the endpoint you want to connect to and click **Connect**.

1. Click **Download CA Cert**.

1. Click **Copy** to copy the connection string:

    - The host address is populated with the address for the endpoint you selected. This is also shown under **Connection Details** for the endpoint.
    - port is 55433.
    - Replace `<DB USER>` with your database username (`cloud_admin` unless you created another role).
    - `postgres` is the default database; replace it if you're connecting to a database other than the default.
    - Replace `<ROOT_CERT_PATH>` with the path to the root certificate you downloaded to your computer.

    If the endpoint has a DocumentDB address, the dialog also offers **DocumentDB**. Select it and copy that command instead.

The client prompts for the password from the credentials file when you run the command.
