Serverless clusters are created in your [Serverless account](/stable/yugabyte-cloud/managed-security/manage-accounts/). This account is created automatically the first time you create a serverless cluster.

To create your first serverless cluster, see [Quick Start](../../cloud-quickstart/).

## Create a serverless cluster

If you have previously created a serverless cluster, do the following:

1. Switch to your Serverless account.
1. On the **Clusters** page, click **Add Serverless Cluster** to open the **Create Cluster** wizard.

The **Create Cluster** wizard has the following pages:

1. [General](#general)
1. [Cluster Settings](#cluster-settings)
1. [Network Access](#network-access)
1. [DB Credentials](#db-credentials)

### General

Enter a name for the cluster.

### Cluster Settings

#### Engine

The engine seeds the cluster with a set of extensions. **PostgreSQL** is the default. The other engines are **AI Database**, **Oracle**, **SQL Server**, and **DocumentDB**. You can select more [extensions](#extensions) on top of the ones the engine includes.

#### Read-write compute

Choose a size:

- **Small**: 2 vCPU and 16 GiB.
- **Medium**: 4 vCPU and 32 GiB.
- **Large**: 8 vCPU and 64 GiB.
- **Custom**: Enter the **vCPU** and **Memory**. Enter vCPU as a number of cores or in millicores (for example, `1500m`), and memory in GiB or MiB. Memory must be at least 8 GiB per vCPU.

Your organization gets 2 vCPU free. If you choose a size larger than the free allowance and the account has no [billing profile](../../cloud-admin/cloud-billing-profile/), you are prompted to create one before the cluster is created.

#### Extensions

Select the PostgreSQL extensions you want to use with your cluster. Extensions the engine already includes are marked **Included with engine**.

The cluster starts with a `main` branch, and you can [fork other branches](../manage/#add-a-branch) from it. The extensions you select are seeded on `main`, and every branch forked from it inherits them. You can add extensions to a branch later, but you can't remove them.

For information on extensions supported in YugabyteDB, see [PostgreSQL extensions](../../../additional-features/pg-extensions/).

### Network Access

Select a **Connectivity Method**. This determines how clients connect to the cluster.

**Public Endpoint** is the default. Enter **Trusted IP Addresses**. Each entry is one address or a CIDR range. Separate several entries using commas.

{{< warning title="Important" >}}

A public endpoint with no trusted IP addresses accepts connections from anywhere on the internet. The database password is the only protection. Do not use `0.0.0.0/0` for production data.

{{< /warning >}}

### DB Credentials

The database user is `cloud_admin`. You can use the default password generated by YugabyteDB Aeon, or add your own.

{{< warning title="Important" >}}

Save the credentials file. You need it to connect, and the console does not show the password again.

{{< /warning >}}

Download the credentials, and click **Create Cluster**.

YugabyteDB Aeon adds the cluster to the **Clusters** page. A new cluster has one [read-write endpoint](../manage/#manage-endpoints), on the `main` branch.

## Connect

Connect to your serverless cluster using [psql](https://www.postgresql.org/docs/18/app-psql.html).

To connect to an endpoint, do the following:

1. On the **Clusters** page, open the serverless cluster.

1. Select the endpoint you want to connect to and click **Connect**.

1. If the dialog offers **Download CA Cert**, click it and save the certificate.

1. Click **Copy** to copy the connection string, which looks like the following:

    ```sh
    psql "host=<HOST_ADDRESS> port=<PORT> user=<DB_USER> dbname=postgres sslmode=verify-full sslrootcert=<ROOT_CERT_PATH>"
    ```

    The host and port are the endpoint's address, also shown under **Connection Details** for the endpoint. In the copied string, do the following:

    - Replace `<DB_USER>` with your database username (`cloud_admin` unless you created another role).
    - Replace `postgres` if you're connecting to a database other than the default.
    - Replace `<ROOT_CERT_PATH>` with the path to the CA certificate you downloaded. If the endpoint doesn't require the CA certificate, the string has no `sslmode` or `sslrootcert`.

    If the endpoint has a DocumentDB address, the dialog also offers **DocumentDB**. Select it and copy that command instead.

1. Run the command. When prompted, enter the password from the credentials file you downloaded when you created the cluster.
