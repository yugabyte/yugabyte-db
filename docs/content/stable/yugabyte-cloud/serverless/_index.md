Serverless Postgres is a fully managed PostgreSQL service in YugabyteDB Aeon. Each agent or tenant gets its own isolated PostgreSQL database. Use it for AI agents and for workloads that are bursty or often idle.

## Features

A Serverless Postgres cluster includes the following features:

- Scale to zero.
- An isolated PostgreSQL database for each agent or tenant.
- Zero-copy branching.
- A path to a distributed YugabyteDB cluster without a migration.
- Built-in connection pooling.
- Fair CPU sharing across tenants.

Your organization has a single account for serverless clusters, created when you create your first Serverless Postgres cluster. YugabyteDB Aeon prepares the environment and the shared pool for you.

Serverless Postgres is free to start, and includes 2 vCPU, 16 GB RAM, and 100 GB storage.

This is shared by everything run in the account. You can upgrade to larger sizes; this requires creating a [billing profile](../cloud-admin/cloud-billing-profile/) for the serverless account. Only Admin users can create a billing profile.

## Create a serverless cluster

If you have previously created a serverless cluster, do the following:

1. Switch to your Serverless account.
1. On the **Clusters** page, click **Add Serverless Cluster** to open the **Create Cluster** wizard.

The **Create Cluster** wizard has the following pages:

1. [General](#general)
1. [Cluster Settings](#cluster-settings)
1. [Network Access](#network-access)
1. [DB Credentials](#db-credentials)

### General

Set the following options:

- **Cluster Name**: Enter a name for the cluster.

### Cluster Settings

#### Engine

**PostgreSQL** is the default. **AI Database**, **Oracle**, **SQL Server**, and **DocumentDB** are the other engines.

The engine determines which [extensions](#extensions) can be included.

#### Read-write compute

Choose a size:

- **Small/Free**: 2 vCPU and 16 GB.
- **Medium**: 4 vCPU and 32 GB.
- **Large**: 8 vCPU and 64 GB.
- **Custom**: Select **vCPU** and **Memory**. vCPU can be from 0.5 to 64; add `m` to enter values in millicores (for example, `1500m`). Memory can be from 1 to 512 GB; you can also enter values in MiB. You must have at least 8 GB per vCPU.

    Your organization is allowed one Free cluster. If you choose an option other than Free and you have not added a [billing profile](../cloud-admin/cloud-billing-profile/) to the account, you will be prompted to create a billing profile before the cluster is created.

#### Extensions

Select PostgreSQL extensions that you want to use with your cluster.


Extensions that the engine includes are marked **Included with engine**.

The cluster starts with a `main` branch, and you can [fork other branches](#add-a-branch) from it. The extensions you select are seeded on `main`, and every branch forked from it inherits these extensions. You can add extensions to a branch later. You cannot remove them.

For information on extensions supported in YugabyteDB, see [PostgreSQL extensions](../../additional-features/pg-extensions/).

### Network Access

Select a **Connectivity Method**. This determines how clients connect to the cluster.

**Public Endpoint** is the default. Enter **Trusted IP Addresses**. Each entry is one address or a CIDR range. Separate several entries using commas.

{{< warning title="Important" >}}

A public endpoint with no trusted IP addresses accepts connections from anywhere on the internet. The database password is the only protection. Do not use `0.0.0.0/0` for production data.

{{< /warning >}}

### DB Credentials

The database admin credentials are required to connect to the YugabyteDB database that is installed on the cluster.

The database user is `cloud_admin`. You can use the default password generated by YugabyteDB Aeon, or add your own.

{{< warning title="Important" >}}

Save the credentials file. You need it to connect, and the console does not show the password again.

{{< /warning >}}

Download the credentials, and click **Create Cluster**.

## Connect

1. On **Clusters**, open the cluster.

1. On the endpoint, click **Connect**.

1. If the dialog includes a CA certificate, click **Download CA Cert**.

1. Click **Copy command** and run it.

    Use `cloud_admin` as the database user, unless you created another role. The client prompts for the password from the credentials file.

    If the endpoint has a DocumentDB address, the dialog also offers **DocumentDB**. Select it and copy that command instead.

## Manage a cluster

To manage a cluster, click **Clusters** in the left navigation and open the cluster. The **Cluster Branches** section lists the cluster's branches, and the compute endpoints on each branch.


### Add a branch

A branch is an isolated, zero-copy version of a database. The cluster starts with a `main` branch, and you fork other branches from it. Creating a branch does not add storage cost. Additional storage is charged only when branch data changes.

1. Click **Add Branch**. To fork from a specific branch, open the actions menu on that branch and click **Add Child Branch**.

1. Enter a **Branch name**. Use a descriptive name, such as a feature, test, or environment name.

1. In **Fork from**, select the parent branch.

1. For **Fork point**, select **Latest state** (recommended) or **Specific LSN**, and enter the LSN to fork the parent from that point.

1. Click **Add**.

The branch actions menu also includes **Add Extensions**, **Edit Postgres Settings** (under **Advanced Settings**), and **Delete Branch**. You can't delete the `main` branch. Extensions can't be removed after they are added, and adding one restarts every compute endpoint on the branch.

### Add a compute endpoint

A branch that has no compute shows **No compute endpoint**.

1. On the branch, click **Add Compute Endpoint**.

1. On **Endpoint Settings**, set the following and click **Next**:

    - **Role**. Choose **Read-Write**. A branch can have one read-write endpoint.
    - **Endpoint name**. The name becomes part of the URL and must be unique within the branch.
    - **Read-write compute**. Choose a size, as when you create a cluster.

1. On **Network Access**, copy the access configuration from an existing endpoint in the cluster, or start from scratch. For a public endpoint, enter the **Trusted IP Addresses**.

1. If the wizard shows **DB Credentials**, set and download the credentials. The `cloud_admin` password is shared by every endpoint on the branch, so setting it here changes the credential that existing endpoints on the branch use.

1. Click **Add Endpoint**.

### Edit compute

1. On the endpoint, open the actions menu and click **Edit Compute**.

1. Select a size: **Small**, **Medium**, **Large**, or **Custom**. The sizes follow the same rules as when you create a cluster. Memory must be at least 8GB per vCPU.

    Free compute is shared by everything the account runs, so a size is free only within what remains. The size you are replacing doesn't count against the free compute. Sizes beyond it are marked **Billed**.

1. Click **Apply Resize**.

    If the new size is billed and your account has no billing profile, you are asked to create one first. If you can't manage billing, ask an account admin.

To remove the compute, click **Delete Endpoint**. Anything connected to the endpoint loses the connection.

## Tasks

Creating, resizing, or deleting a resource records a task. To see a task's progress, or the error if it failed, click **Tasks** in the left navigation and open the task.
